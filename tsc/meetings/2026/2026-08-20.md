# MoonRay TSC Meeting - August 20, 2026
## Quick Recap
The meeting focused on discussing OpenQMC integration with MoonRay and updates on Hydra 2.0 support.

The main discussion centered on Mike and Ashley evaluating OpenQMC as a potential replacement for MoonRay's current sampling system.
Josh from Framestore explained that OpenQMC aims to provide a ready-to-use solution with state-of-the-art techniques that renderers can integrate
as a black box, and discussed the project's adoption by various studios including Epic, Illumination, and Netflix. The DWA team agreed to create a
GitHub issue to track the MoonRay-OpenQMC integration efforts and transition their internal JIRA ticket to GitHub for better public visibility.

Rob then discussed his work on Hydra 2.0 support for MoonRay, which includes clean-up changes to support Hydra 2 clients like Houdini 21 and Maya
2026, and plans to create a branch for these changes rather than merging directly to main for now.

The conversation concluded with a discussion about managing the transition from internal development to open source engagement, with Josh sharing
OpenQMC's experience of treating the project like a third-party dependency even for internal testing.

## Summary
### Windows Development Progress Update:
Duncan inquired about updates on Windows development, noting that their team needs to update their code due to significant progress since their last
update. Jon reported that the developers working on Windows haven't yet shared their plans for contributing back through pull requests.

### OpenQMC Implementation Discussion:
Jon led a discussion about OpenQMC with Mike Day and Ashley Lee from DWA, who explained that the previous engineer who had focused on sampling had left
the studio, leaving the project unfocused. Mike noted that MoonRay's existing QMC sampling had several shortcomings due to limited resources, making
an out-of-the-box solution with state-of-the-art techniques a good fit. Josh explained that the goal of OpenQMC is to provide a stable API that stays
current with the latest research, and he inquired about MoonRay's specific requirements, particularly regarding ISPC support.

Mike and Ashley reviewed OpenQMC documentation and found it could serve as a straightforward drop-in replacement for their current system.
Josh asked whether MoonRay would need runtime sampler switching capabilities, with Mike confirming that such flexibility would primarily benefit developers
rather than end users. Josh and Mike discussed implementation approaches, including the possibility of using scalar mode for prototyping and the potential
need for SIMD support in the future, though this was deemed a lower priority for an initial implementation.

Josh agreed to advise and support the OpenQMC MoonRay integration project. Jon explained that moving internal projects to public GitHub issues would
provide better visibility and allow for community collaboration on the MoonRay integration. The team discussed starting with an initial investigation
to assess feasibility and identify both short-term and long-term approaches for the integration.

Paul expressed interest in understanding how the threading model might interact with MoonRay's existing design, particularly regarding cache
memory and thread isolation. Josh explained that their current approach uses lightweight, stack-based memory with strict 8-byte element constraints to
minimize cache line issues. The team agreed to create an initial ticket that would include information about existing samplers and the MoonRay API.

Josh discussed the positive engagement and contributions to the OpenQMC project, highlighting adopters like Cisco, Illumination, and others, and noted
the project's growing momentum with new implementations and discussions.

Jean-Francois suggested creating a Conan recipe in ASWF Docker for MoonRay.

### Hydra 2.0 Support Planning:
Rob discussed the work-in-progress Hydra 2.0 support for hdMoonray, which includes changes to support Hydra 2 clients like Houdini 21 and Maya 2026. We
decided to create a branch rather than merging the changes to main, for now,  as we need to review build requirements and CI implications. The group
also discussed USD version support, agreeing to set USD 25.5 as the minimum version and update build recipes accordingly. Jean-Francois mentioned
that the 2027 MoonRay containers will include USD 26.08.

### Other:
The team explored challenges around balancing internal development needs with open source contributions, with Josh sharing OpenQMC's experience of
managing this transition. They also discussed regression testing approaches, including the use of RATS test suites and handling non-deterministic
behavior in vector mode.
